# 기존 운영판 담임 열람 제한 적용 계획

대상: BoscoHeo1/classdivide 운영 main e0436ee, Firebase class-divide.

1. 관리자 전체 학급 권한과 기존 회원·학생 자료·복구 코드를 유지한다.
2. 담임은 서버가 확인한 기존 담당 학급의 명단·비고·배정 결과만 받는다. 새 학급 전체 명단과 학년 통계는 제공하지 않는다.
3. RTDB 규칙에서 담임의 방 전체·다른 반·전체 결과 직접 조회를 차단한다.
4. 학생 자료 주기 조회를 없애고 입장·저장·최신 자료 불러오기 때 갱신한다. 권한·참여 알림은 유지한다.
5. 가상 자료로 규칙·함수·복구·브라우저·기존 결과 호환·비례 목표를 검증한다.
6. 기존 소스·배포·규칙·함수 코드를 보존한다. 함수 → 화면 → 규칙 순서로 배포해 호환성을 유지하고, 가상 시험방만으로 최종 점검한다.
7. 구버전 담임 탭은 규칙 전환 후 접근 오류가 날 수 있으므로 저장 후 새로고침·재입장이 필요하다. 이미 내려받은 자료와 과거 브라우저에 표시된 자료는 회수할 수 없다.

실제 학생 자료는 열거나 수정하지 않는다. 학급별 데이터 이동/마이그레이션과 기존 회원·관리자 권한 삭제는 하지 않는다.

## 사전 검증
- 기존 배정20개, 비고 서버32개·클라이언트18개, 탭 저장7개, 특이사항9개 통과.
- 담임2명별 자료 투영·전체 비고 관리자 유지·잘못된 권한 차단 검사 통과.
- 실제 로컬 RTDB 규칙: 전체 방·타반·전체 결과 조회 거부, 본인 조회/쓰기와 관리자 전체 권한 유지 확인.
- 실제 Auth/RTDB/Functions 브라우저 통합26개 통과. 유휴16.5초 동안 학생자료·비고 반복 요청 없음.
- TypeScript·운영 빌드 통과. 운영 번들에 demo 프로젝트/에뮬레이터 주소 없음.
- 기존 운영 규칙이 소스 e0436ee의 규칙과 동일함을 확인하고 학생자료를 조회하지 않은 채 규칙 사본을 보관함.
- 새 getTeacherWorkspace와 listStudentRemarks 함수를 먼저 운영 배포함. 관리자 복구·저장 함수는 그대로 유지함.
